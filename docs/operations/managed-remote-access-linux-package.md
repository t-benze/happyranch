# Managed remote access: Linux package operations (N3)

N3 composes the portable Python connector and embedded Linux tsnet sidecar into one reproducible owner-only artifact. It does not provision a control plane, deploy a service, enable managed access by default, or begin macOS work.

```sh
cd app/linux/tsnet-sidecar
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -buildvcs=false -o ../../../dist/happyranch-tsnet-sidecar ./cmd/happyranch-tsnet-sidecar
python tools/generate_inventory.py
cd ../../..
uv build --wheel --out-dir dist
uv run python app/linux/package/build_connector.py --wheel dist/happyranch-0.1.0-py3-none-any.whl --output dist/happyranch-connector
uv run python app/linux/package/build_package.py --sidecar dist/happyranch-tsnet-sidecar --connector dist/happyranch-connector --wheel dist/happyranch-0.1.0-py3-none-any.whl --version 0.1.0 --output dist/happyranch-linux-amd64.tar
```

The manifest hashes every payload. `share/sbom.cdx.json` and `share/THIRD_PARTY_NOTICES.md` couple to the exact checksum-pinned N1 inventory; composition refuses a module missing from the notices. No dependency resolution occurs during composition.

`build_connector.py` installs the real wheel into an isolated build target and freezes that installed code with the repository-pinned PyInstaller build dependency. The archive therefore carries an explicit self-contained Python executable; it never relies on a source checkout, ambient `python`, or an inert wheel as launch proof. The wheel remains bundled as an exact receipt.

The composite starts the connector and runs its supported `diagnose --config` preflight before sidecar admission. The sidecar is a truthful `Type=notify` executable whose config carries owner-custodied state plus the private Headscale URL, `private-only` DERP policy, role identity, expected peers, listener, and loopback connector target. Enrollment input comes exclusively from `$CREDENTIALS_DIRECTORY/enrollment.key` staged by systemd `LoadCredential`; config path indirection is overwritten, the staged file is never copied or unlinked by the service user, and `StateDirectoryMode=0700` is explicit. Startup reports READY only after durable enrollment, peer visibility, connector reachability, and listener activation. Only then an elevated `ExecStartPost` helper atomically rename/fsync/deletes the owner-only source `/etc/happyranch/enrollment.key`; it restores a pre-retirement rename when the durable marker is absent and safely finishes or re-enters retirement when the marker is present. Optional `LoadCredential=-...` permits enrolled-state restarts without re-reading a key, while marker-plus-still-staged-key fails closed. Server-side one-use redemption and <=10-minute expiry remain authoritative. While healthy the sidecar emits WATCHDOG every ten seconds for the unit's 30-second watchdog; notification failure terminates the service so systemd restarts it. Target stop removes sidecar admission before connector cleanup. Unit and package files are owner-only; the sidecar never receives the daemon bearer.

The dedicated `Managed N3 Real systemd (Ubuntu 24.04)` CI job is fail-closed and zero-skip. It qualifies PID 1, the system manager, passwordless sudo, and transient units; verifies native Headscale v0.25.1 sha256 `d2cda0a5d748587f77c920a76cd1bf1ab429e5299ba5bc6b3dda90712721b45b` and the reused CI-only Tailscale 1.102.3 peer tarball sha256 `36ddd9b51be57ffc2990cf76323cfa13643bfbb1b8a969f6183fa164741cdef5`; then requires the packaged production tsnet sidecar to see `synthetic-peer-ci` through `ExpectedPeers` before systemd READY. Both artifacts are BSD-3-Clause and already covered by the existing CI-lab artifact policy; this unit introduces no new distributed package input or notices duty. The genuine peer probes the virtual TSNet `:443` listener directly; host port 443 and connector port 18443 are not admission evidence. Explicit systemd barriers force start-entered-before-stop and stop-completed-before-start orderings. Two clean service generations each emit a category-only receipt only after production `Sidecar.Stop` has removed the listener, drained flows, and completed its once-guarded engine close. Real installer checkpoint faults cover fresh installation and live upgrade rollback before successful re-entry. The semantic lifecycle contract is complete only after all mapped observations execute, every spawned process is waited and reaped, and host listeners, units, package/state paths, transaction markers/backups/stages are absent. N3 does not exercise or claim admitted HappyRanch requests or authorization-negative behavior; those proofs remain N6.

The installer validates duplicate-free exact archive/manifest membership against a closed path set, normalized paths, strict non-boolean schemas, architecture, count, hashes, and modes before any write. Inventory and CycloneDX fields (coordinate, purl, SPDX, go.sum and license checksum) plus structured notice coordinates/SPDX/checksum/content match one-to-one. A durable owner-only transaction marker classifies publication state. On re-entry it either restores the last-known-good payload and units and removes staging residue before a fresh install, or rejects an incoherent marker/backup composition; it never silently deletes an unexplained backup.

Install/upgrade/uninstall functions take an explicit fixture root and validate the manifest before mutation, enabling tests without touching the host. Production installation, service enablement, deployment, signing, and launch remain gated.
