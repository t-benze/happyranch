**Web (Main SPA, S6-W3 #1811):** The Connection dialog consumes:

- `app.status`/`app.stateChanged` (#1774 store);
- `client.status`, `client.savedComputers`, `client.acceptInvite`, `client.connectSaved`, `client.removeSaved`, `client.cancelAttempt` (dialog + owner-gate row), `client.retry`, `client.retrySave` and `client.health`;
- `client.commitSwitch` and `client.disconnect`. Both run after the owner gate, the `app.ownersChanged` receipt and the save hold. Both are bound to the candidate/target the user chose (kind + id): if that changes, nothing is sent and a fresh explicit action is required. A save whose result is unknown (including a 499 cancelled interrupted save) holds the owner gate: nothing is sent until same-owner Check result.
- `host.status`, `host.stateChanged`, `host.enable`, `host.turnOff`, `host.createInvite`, `host.approveDevice`, `host.rejectDevice`, `host.nextDevice` and `host.revokeDevice`. An unknown-effect host action stays unconfirmed until a newer successful `host.status` or `host.stateChanged`.

Saved computers are marked current only for the committed remote target. `client.stateChanged` and `bridge.hello` are not used on Main: it re-reads on `app.stateChanged`, and capability is detected by `unsupportedCommand`. Linux S7-L1 (#1813) retires the native Connection window and routes the header/badge through `app.dialogRequested` to Main.

The spec's current implementation table also records each existing ordinary
request/transport code and exact Linux source lines. V2 errors have only
`detail.code`, plus optional `detail.side` for incompatible; existing v1
